## Interpretación y alcance

Inventario AST de los siete routers incluidos por `backend/app/main.py:106–112`, sin importar la aplicación ni conectarse a servicios: **208 operaciones /api**, 207 handlers (un alias de reporte), más 2 de sistema y 4 automáticas de documentación: **214 operaciones HTTP**. El alias `/reportes/convenios/destinos` comparte función/política con `/reportes/convenios/colectivos-destino`. OPTIONS de CORS no se contabiliza como operación de negocio. Snapshots OpenAPI históricos no son la autoridad de este inventario.

Las columnas indican admisión por rol, condicionada al recurso/alcance: `Sí*` no significa acceso a todos los objetos. `—` deniega el rol. `Pública` no requiere sesión; login exige Origin permitido y logout con cookie exige CSRF. Usuario inactivo/revocado/vencido se rechaza antes del control de rol. Las escrituras POST/PUT/PATCH/DELETE bajo /api con cookie requieren Origin, cookie/header CSRF y hash enlazado a sesión.

La columna de controles sigue llamadas de Python a servicios locales hasta cinco niveles: **evidencia estática, no prueba dinámica ni garantía de todos los caminos**. El modo se muestra tal como aparece en la llamada; `default` requiere consultar la firma del helper. Sin `limit` en la firma no demuestra que el servicio carezca de toda cuota. La ubicación exacta permite revisar condiciones y parámetros adicionales. Ninguna fila fue ejercitada contra HTTP real en esta auditoría.
