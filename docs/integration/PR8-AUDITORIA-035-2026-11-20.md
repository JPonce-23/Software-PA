Fecha: 2026-11-20. **El defecto de auditoría queda corregido y validado en PA5-QA. Recomendación global: NO MERGE todavía**, por la validación/suministro pendiente del backend GDAL 3.13.3 ABI39. ## Causa raíz y revisión SECURITY DEFINER

Se revisaron las 34 migraciones históricas completas. El inventario mediante AST PostgreSQL identifica **una función SECURITY DEFINER única de la aplicación**, `public.fn_audit_log()`, con cuatro definiciones en 001, 010, 011 y 020. La efectiva antes del arreglo es la de 020. Las coincidencias en comentarios de 009 no son funciones adicionales. Se comprobaron también ALTER FUNCTION/dynamic SQL; no hay otra elevación SECURITY DEFINER declarada por esas migraciones. El catálogo real de ambos laboratorios confirma una función de aplicación, excluyendo objetos pertenecientes a extensiones.

| Hallazgo | Severidad y evidencia | Tratamiento |
|---|---|---|
| Destino `bitacora` sin esquema y `search_path=public` | Alta: TEMP implícito podía preceder a public; auditoría escrita en una tabla temporal | 035 califica public.bitacora y fija ruta segura |
| Lecturas sin esquema de evento_acceso, convenio, afectacion, indemnizacion y proyecto_nucleo | Alta dentro del contexto privilegiado: susceptible a homónimos temporales y correlación/contexto incorrectos | Todas las relaciones persistentes quedan calificadas |
| Reutilización de fn_audit_log en trigger de tabla temporal propia | Alta para integridad: antes se pudo registrar una operación ficticia como si perteneciera a proyecto | Nueva guarda TG_TABLE_SCHEMA='public'; regresión roja/verde real |
| Permiso TEMP heredado de PUBLIC | Capacidad efectiva confirmada, no se clasifica como defecto por sí sola | Se conserva. La corrección aprueba con temporales presentes |
| EXECUTE de función trigger por defecto y owner privilegiado | Contexto que hizo posible el uso como deputy; no se amplió la ACL | Owner/ACL/OID preservados; la guarda bloquea el uso fuera de public |

`pg_catalog` es confiable; public debe permanecer no escribible por el grupo runtime, condición comprobada antes de reemplazar la función y en el laboratorio para qa_runtime. `pg_temp` es escribible por la sesión y se coloca explícitamente al final. No se revocaron privilegios de PUBLIC, TEMP, roles ni esquemas globales. El orden explícito de pg_temp sigue la [guía oficial de funciones SECURITY DEFINER de PostgreSQL15](https://www.postgresql.org/docs/15/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY).

La función usa primitivas de pg_catalog (`current_setting`, `to_jsonb`, `txid_current`, conversiones y operadores JSON/SQL); no llama funciones auxiliares personalizadas de la aplicación. Con pg_catalog primero, tipos, operadores y built-ins no dependen del search_path del llamador. Los triggers hermanos de autenticación, por ejemplo fn_auth_validar_estado_evento, son INVOKER, no otras funciones elevadas; conservan referencias históricas sin calificar. No se afirma haber endurecido todo el namespace de funciones INVOKER ni probado todos sus casos: esta corrección cubre el trigger privilegiado y las regresiones descritas. Las comprobaciones de correlación de expiración dentro de fn_audit_log sí se ejercitaron ante un evento temporal falso.

El defecto es preexistente en dev y en f715b55: no lo introdujo el runtime +pa5. No se ensayó contra patrenes. La prueba presupone ejecución SQL como runtime; no se demostró una vía de ataque HTTP.
